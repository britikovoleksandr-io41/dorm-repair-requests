# 0003. GitHub Actions, OCI і staging

Статус: запропоновано.

## Контекст і варіанти

Тестовий раннер ізолює PostgreSQL від staging. Сервіс має повертати SHA образу й приймати трафік після перевірки БД. Розглянуто збирання на хості deployment та передачу готового OCI-образу через реєстр.

## Рішення та наслідки

GitHub Actions перевіряє PR і main. Після успішної перевірки push у main збирає OCI-образ з SHA, публікує у GHCR і передає digest у deploy hook Render. Render налаштовується на `/ready` і здійснює перемикання трафіку після готовності контейнера. У раннера є URL deploy hook і публічна URL staging. PostgreSQL DSN та токени акторів задаються середовищем Render.

Структурні міграції працюють у контейнері до відкриття порту та серіалізовані advisory lock. Вони мають бути сумісні з версією, яка обслуговує трафік. Міграція 001 створює таблиці й індекс історії на порожній таблиці. Створення індексів на заповненій таблиці — окрема операція `CREATE INDEX CONCURRENTLY`. Backfill і підготовка користувачів запускаються окремо від контейнерного старту.
