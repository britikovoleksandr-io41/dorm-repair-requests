# 0002. Ініціатор і контекст запиту

Запропоновано до погодження.

## Контекст і варіанти

Прикладні логи HTTP, сервісу й БД мають спільний ID. Явний параметр контексту робить залежність видимою в сигнатурах. AsyncLocalStorage зберігає контекст асинхронного запиту в одному місці. DI-контейнер потребує додаткового механізму області життя.

## Рішення та наслідки

Кореневий HTTP-обробник створює UUID й ініціатора в AsyncLocalStorage. Структурований логер читає їх з поточного контексту за кожного запису. Ресурси передаються явно через фабрики. Токени, тіла запитів і SQL-параметри не потрапляють у логи. Для публічних, неавтентифікованих і позазапитних операцій поле ініціатора порожнє. Службові записи поза HTTP мають також порожній ID.
