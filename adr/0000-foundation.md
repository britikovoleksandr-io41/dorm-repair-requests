# 0000 · Перевіряти Git-зріз єдиною командою

- Статус — запропоновано, погодження студента очікується.
- Дата запису — 2026-11-24.
- Ревізія реалізації, яку описано, — `52ff4b8`.

## Контекст і проблема

ЛР1 має відхиляти брудний коміт і перевіряти той код, який потрапить до Git. У робочому каталозі одночасно можуть бути staged та unstaged зміни. Перевірка лише робочих файлів у такому разі досліджує інший стан.

## Критерії рішення

- Одна команда для форматування, лінту, збірки й smoke.
- Pre-commit аналізує індекс, pre-push аналізує дерево кожної гілки, що передається.
- Встановлення зберігає наявний локальний hook, якщо він відрізняється.

## Розглянуті варіанти

- Запуск `npm run check` у робочому каталозі. Просте налаштування, зате виправлення в unstaged-файлі може приховати проблему у staged-зрізі.
- Перевірка staged-файлів окремими командами. Скорочує роботу форматтера й лінтера, але збірка і smoke потребують повного узгодженого дерева.
- Окремий Git-зріз для кожного hook і спільний `npm run check`. Перевірка відповідає ревізії, що передається, ціною створення тимчасового дерева.

## Рішення і наслідки

Робоча реалізація використовує `git checkout-index` для pre-commit і `git archive` для pre-push. Обидва запускають однаковий набір перевірок. Витрати залежать від розміру дерева та доступності встановлених залежностей. Git не вмикає відстежувані hooks автоматично після clone, тому встановлення є окремим кроком. GitHub CI на наступному етапі забезпечує окрему перевірку перед merge.
