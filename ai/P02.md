> Користувач дозволив доопрацювати локальні артефакти здачі ЛР1–ЛР5 для [вилучено ім’я студента] після аудиту DoD. Продовж у своєму наявному репозиторії. > Зроби коротку специфікацію для кожної ЛР до однієї сторінки з метою й вимірюваними критеріями приймання, легко знайдену з README. Збережи корисні деталі наявної накопичувальної специфікації. Познач як чернетки ті вимоги та рішення, які студент ще має погодити. Додай ADR у форматі MADR на ключове рішення ЛР1, описавши фактичні альтернативи й наслідки, без твердження, що студент вже погодив рішення.
>
> Створи в репозиторії ai/ з реальним слідом використання AI. У своїй історії доступний первісний фактичний запит від 23 листопада до всіх п’яти лаб. Збережи його один раз під стійким локальним ідентифікатором на зразок P01 і віднеси до ЛР1–ЛР5 через посилання на відповідні фрагменти, коміти і перевірки. Окремі записи додавай лише для запитів, які справді існували. Збережи суттєвий технічний текст, дату, а також подальші фактичні промпти, що вплинули на результат. Прибери приватні абсолютні шляхи, персональні дані й службові деталі середовища. Познач вилучення. У матеріалах для здачі використовуй локальні Markdown-посилання, без назв чи URL платформи оркестрації. Факт використання OpenAI Codex відображай прозоро. Не перетворюй один реальний запит на п’ять вигаданих та не створюй фіктивний діалог.
>
> По кожній ЛР звір три реальні розбіжності або зрізані кути з доступними доказами. Для кожної вкажи відповідний промпт або його фрагмент, фактичне спостереження, фідбек-коментар (новий можна додати поточною датою з чесною атрибуцією), уточнений критерій чи стандарт, ревізію виправлення, команду та результат. Якщо старого фідбеку чи підтвердження нема, назви це прямо. Не вигадуй знахідок заради заповнення трьох рядків. Для нових перевірок зберігай тільки фактичний результат.
>
> Зроби в README або окремому короткому індексі по ЛР1–ЛР5 входи на spec, ADR, аудит, команду, докази, відповідний SHA і стан майбутнього PR. Студент сам заповнює односторінковий DEFENSE: мета 1–2 речення, топ-3 з комітами, рішення й альтернативи з ADR, команда перевірки, її результат і SHA з /version там, де ендпойнт існує. Можеш зібрати посилання й факти як підготовку, зберігаючи авторство; не пиши DEFENSE від імені студента.

Для ЛР4 залиш у документації конкретні кроки і відділи локальні докази від ще не підтверджених GitHub checks, merge gate та публічного staging. МКР тут не виконувати, умови ще нема.
