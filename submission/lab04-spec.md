# ЛР4 · CI та staging

**Мета** — перевіряти PR, запускати готовий контейнер з міграціями та підтверджувати розгортання за SHA.

**Статус** — чернетка для погодження студентом. GitHub Actions, GHCR, Render і правила merge запропоновані. [ADR](../adr/0003-container-staging.md).

## Критерії приймання

1. Локально `actionlint` і перевірка Conventional Commits завершуються з кодом 0. `make ci-negative` виявляє спеціально неформатований файл, завершується кодом 2 і прибирає файл.
2. Контейнер застосовує структурні міграції перед запуском HTTP. Тестований образ віддає 200 на `/ready`, проходить сценарій ремонту і повертає в `/version` SHA збірки. Після зупинки БД `/ready` дає 503, а `/health` — 200.
3. На GitHub job `Verify` є обов’язковим для `main`. PR з позначеним порушенням має червоний check і заблокований merge. Після виправлення check стає зеленим. Для обох станів потрібен доказ із GitHub.
4. Після push у `main` успішний workflow публікує образ за digest і розгортає його на публічному staging. `/ready` повертає 200, `/version` дорівнює SHA цього push. Сценарій черги та переходу статусу проходить у цьому середовищі.
5. CI використовує окрему БД. Дані staging та токени розміщує середовище deployment. Перемикання трафіку підтверджується після успішної перевірки готовності.
