# ЛР3 · Перевірка переходів

**Мета** — перевірити критичні правила заявки на рівнях unit, PostgreSQL integration та HTTP E2E, а також виміряти чутливість unit-тестів до змін.

**Статус** — чернетка для погодження студентом. Межі мутаційного прогону і критерії доказу конкурентності є робочими рішеннями. [Накопичувальна специфікація](../spec.md#перевірки-лр3).

## Критерії приймання

1. `make test` запускає збірку, unit, smoke, integration та E2E. Тести правил переходів покривають усі гілки `src/policy.js`, ролі, призначення і вимогу примітки.
2. Інтеграційний тест бачить обидва запити майстрів у стані очікування блокування. Після зняття блокування результати — 200 та 409, у історії рівно одна подія призначення. Інший тест перевіряє відкат після помилки запису події.
3. E2E виконує створення, призначення й закриття через HTTP, перевіряє видимість для двох мешканців і читає історію через другий процес.
4. `make mutation` дає відтворювані звіти Stryker для `src/policy.js`. Усі вижилі мутанти класифіковані. Усунення прогалини підтверджує повторний прогін.
