# ЛР5 · Вимірювання і бібліотека черги

**Мета** — локалізувати найдорожчий сценарій читання, виділити його межу в TypeScript і виміряти наслідки на однаковому навантаженні.

**Статус** — чернетка для погодження студентом. SQL-індекс, межа `QueueReader`, параметри навантаження та компроміс читання й запису потребують погодження. [ADR](../adr/0004-repair-queue.md).

## Критерії приймання

1. Для базової та зміненої ревізій `make -s load` і `make -s profile` виконують по три повтори. Склад даних, вісім клієнтів і набір операцій в обох ревізіях збігаються. `/version` підтверджує код кожного запуску.
2. Для черг майстра й мешканця, claim і resolve зберігаються p50/p95/p99 HTTP та клієнтського часу SQL. У профільних повторах зберігаються CPU, peak RSS, V8 idle і хеш сирого профілю. Висновок розрізняє час SQL у клієнті та час плану PostgreSQL.
3. `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` для фактичного SELECT показує тип плану, рядки й буфери до і після. Порівняння містить показники запису навіть за погіршення. Поріг прийнятної затримки на staging ще потребує погодження.
4. Пакет `@dorm/repair-queue` збирає JS і декларації, отримує `QueueReader` через DI й не імпортує `pg`. Тести проходять після винесення, контейнер завантажує пакет, а повторний запуск `npm run db:indexes` повертає `index already valid`.
